# Масштабирование, пилот и риски

Документ отвечает на требования кейса к потенциалу масштабирования и сценарию пилотного
запуска: что переносится в новый контекст без изменений, что придётся адаптировать, с кого
начинается внедрение и по каким показателям оценивается результат.

## Ядро продукта

Переносится без изменений в любой дом и любую управляющую организацию:

| Часть | Почему не меняется |
| --- | --- |
| Пользовательская проблема | заявка без номера, статуса и срока существует везде, где домом управляет организация |
| Логика сценария | обращение, приём, назначение, отчёт, приёмка: последовательность задана Правилами № 416, а не конкретной компанией |
| Архитектура | предметный слой, прикладной слой с портами, адаптеры чата, приложения и HTTP |
| Базовая модель данных | дом, помещение, житель, заявка, прибор учёта, начисление, собрание |
| Механика взаимодействия | чат-бот и мини-приложение в MAX, наклейки с кодами объектов, уведомления |
| Ключевые элементы интерфейса | список заявок, карточка заявки со сроком, очередь смены, квитанция |

## Переменная часть

Настраивается при переносе, код при этом не меняется:

| Что настраивается | Где это делается | Стоимость переноса |
| --- | --- | --- |
| Дом, адрес, часовой пояс, код для номеров заявок | карточка дома в приложении или команда `building` | минуты |
| Список помещений, площади, приборы учёта | импорт CSV в разделе «Карточка дома» | выгрузка из учётной системы организации |
| Оборудование и коды объектов для наклеек | импорт CSV, печать листа наклеек из приложения | один обход дома |
| Тарифы, нормативы, ключевая ставка | раздел «Тарифы» | справочник организации |
| Регламент сроков по категориям | таблица категорий в предметном слое | правка конфигурации при сборке |
| Контакты, режим работы, аварийная служба | карточка дома | сведения организации |
| Роли сотрудников и дежурство | раздел «Люди дома» | назначение управляющим |
| Несколько организаций на одной установке | владелец дома (`companyId`), дома чужой организации не видны | заведение второй организации командой `add-building` |
| Домофония, платежи, распознавание речи | переменные окружения и адаптеры портов | договор с поставщиком |

## Куда переносить в первую очередь

| Контекст | Почему подходит | Что потребуется |
| --- | --- | --- |
| Другие дома той же управляющей организации | смена уже работает в продукте, справочники заведены | импорт помещений и печать наклеек |
| Другая управляющая организация того же города | тот же регламент, тот же часовой пояс | заведение организации, свои тарифы и контакты |
| ТСЖ и ЖСК | 53 тыс. домов, своей ИТ-службы у них обычно нет (допущение команды, из числа домов не следует) | упрощённый набор ролей: председатель вместо диспетчера и управляющего |
| Организация в другом регионе | часовой пояс и тарифы уже параметры | проверка регионального регламента сроков |
| Застройщик с собственной эксплуатирующей компанией | новостройка заводится одним импортом | шаблон дома на этапе сдачи |

Направление, которое сознательно не берётся в первую очередь: муниципальные и региональные
платформы обращений. Там другой пользователь, другой регламент и обязательная интеграция
с ведомственными системами.

### Конкретные контексты первого переноса

Требование канала задано федерально, а не пилотными регионами: постановление № 40 обязывает
все управляющие и ресурсоснабжающие организации взаимодействовать с жителями через MAX
с 1 сентября 2026 года. Поэтому выбор первого контекста определяется не «где разрешено»,
а тем, где переход уже идёт и где организация меньше по размеру.

| Контекст | Чем обоснован | Статус утверждения |
| --- | --- | --- |
| Республика Саха (Якутия) | регион уже переводит региональные сервисы и домовые чаты в MAX в рамках национального проекта, жители привыкли к каналу ([ЯСИА, февраль 2026](https://ysia.ru/zhiteli-yakutii-mogut-poluchat-gosuslugi-cherez-natsionalnyj-messendzher-max/)) | факт: публикация регионального агентства |
| Республика Татарстан | заметный рост обращений в жилищную инспекцию и публичная повестка по подготовке домов к зиме: у организаций есть повод показать управляемые сроки | факт: сводка ГЖИ за 8 месяцев 2026 года, см. [`problem.md`](problem.md) |
| Города с крупными управляющими организациями, кроме Москвы | в Москве взаимодействие может идти через региональные системы, поэтому первый перенос удобнее вне неё | допущение команды, проверяется при выходе на организацию |
| ТСЖ и ЖСК любого региона | 53 тыс. домов, у них нет своей ИТ-службы | факт по числу домов, оценка бюджета, допущение команды |

Отдельно: 68 тыс. организаций ведут около 950 тыс. домов (Минстрой, май 2026), то есть
на организацию приходится в среднем 14 домов. Это и есть шаг тиражирования: одна установка
закрывает организацию целиком, а не один дом.

## Пилотный запуск

| Вопрос | Ответ |
| --- | --- |
| Для кого и где | одна управляющая организация, 3-5 домов, 500-1500 помещений |
| Как встраивается в процесс | продукт становится каналом приёма заявок рядом с телефоном; диспетчер работает в очереди, а не в журнале; телефон остаётся для тех, кто не в MAX |
| Какие данные нужны | список помещений с площадями, приборы учёта, тарифы, список сотрудников, коды объектов |
| Какие участники нужны | управляющий как владелец процесса, диспетчер, двое мастеров, старшие по подъездам для первого набора жильцов |
| Что нужно от команды | подключение одной организации: полдня на установку и импорт помещений, день на заведение тарифов, контактов и смежных организаций, печать наклеек; дальше сопровождение по переписке |
| Смежные организации | в карточке дома заводятся ресурсники по видам ресурса, подрядчик по лифтам, муниципальная служба и жилищная инспекция: без них передача обращения записывается, но адресата у неё нет |
| Как жильцы попадают в сервис | наклейки с кодами объектов в подъездах и на оборудовании, ссылка в квитанции, объявление в общем чате дома, привязка квартиры по коду из квитанции |
| Что измеряем | доля заявок в срок, время до первой реакции, доля повторных обращений, доля заявок без звонка, доля принятых жильцом работ |
| Сколько длится | один расчётный месяц: он захватывает и окно подачи показаний, и квитанцию |
| Что дальше при успехе | остальные дома организации, затем вторая организация того же города на той же установке |

Продукт считает все показатели пилота сам: сводка по дому и выгрузка реестра заявок дают
и текущие значения, и сравнение с прошлым периодом.

## Риски и ограничения

| Риск | Последствие | Что делает продукт |
| --- | --- | --- |
| Часть жильцов не пользуется MAX | заявки идут мимо продукта | диспетчер заводит заявку по телефонному звонку от имени квартиры, история дома остаётся полной |
| Данные о помещениях у организации в плохом состоянии | площади и приборы неверны, начисления расходятся | импорт сообщает о проблемных строках, дом заводится частями |
| Смена не переходит в новый инструмент | заявки принимаются, но не двигаются | нарушенный срок виден управляющему, а не только надзору |
| Нет интеграции с биллингом | двойной ввод начислений | выгрузки CSV и XLSX как обмен на первом этапе |
| Ложная склейка обращений | разные поломки попадают в одну заявку | склейка только по совпадению адреса и вида работ, обращение всегда можно оставить отдельно |
| Персональные данные жильцов | ответственность организации по 152-ФЗ | продукт хранит минимум: имя из MAX, телефон по согласию, номер помещения; профиль удаляется, история дома обезличивается |
| Размещение установки | требование размещать базы персональных данных на территории России | установка разворачивается на площадке организации или на российском хостинге, продукт к площадке не привязан |

## Что понадобится для перехода от пилота к тиражированию

1. Адаптер биллинга организации вместо импорта и выгрузок.
2. Обмен с ГИС ЖКХ по её протоколу вместо файлов.
3. Каталог регламентов: сроки по категориям как настройка организации, а не как таблица сборки.
4. Роль председателя ТСЖ, объединяющая управляющего и диспетчера.
5. Многоустановочная эксплуатация: мониторинг, резервное копирование, обновления без простоя.
