# Лендинг «Домовой»

Главная, одиннадцать страниц разделов и две страницы документов продукта. Каждый экран
продукта на странице настоящий: это снимки мини-приложения со стенда, а не нарисованные
макеты.

Vite 6 + React 19 + TypeScript, четырнадцать статических страниц: у каждой свой адрес,
заголовок и og-описание, клиентского роутера нет и SPA-фоллбек хостингу не нужен.

```
npm run dev -w @bezslavie/landing      # http://localhost:4173
npm run build -w @bezslavie/landing    # tsc --noEmit + vite build → landing/dist
```

Домен: `domovoy.homes`.

## Что где лежит

| `src/components/Parts.tsx` | шапка с разделами, мокап телефона, подвал |

| `src/components/Ink.tsx` | узор, который рисуется кистью |
| `src/reveal.ts`, `src/snap.ts` | появление при прокрутке и привязка к экранам |
| `src/styles/motion.css` | всё движение |
| `docs/split-logo.py` | сборка вязи и логотипа из исходника |

Новый раздел заводится в двух местах: запись в `SECTIONS` и файл `<id>/index.html`
(идентификатор в `vite.config.ts` подхватывается оттуда же). Страницы документов перечислены
в `vite.config.ts` отдельным списком `LEGAL`.

## Снимки экранов

Снимаются со стенда: стенд поднимается командой `DATABASE_URL=… HUB_SECRET=demo npm run
stand`, дальше puppeteer открывает `stand.html?startapp=go-<раздел>&as=<maxUserId>`,
при необходимости нажимает кнопки и снимает рамку приложения. Данные для съёмки берутся
из отдельной базы, засеянной `cli.js seed`: в рабочей базе стенда лежат следы проверок. Высота у всех одна (390×800), сверху лендинг дорисовывает строку
состояния: иначе корпус телефона на странице выглядит сплюснутым.

Перед съёмкой у рамки эмулятора снимается скругление (`border-radius: 0`): иначе в углы
кадра попадает чёрный корпус, и на странице он торчит из-под строки состояния уголками.
Проверить готовый снимок просто: все четыре угла должны быть цветом фона приложения,
а не тёмными.

Мокап телефона в `Parts.tsx` считает размеры от своей ширины (`cqw`), поэтому
строка состояния, островок и клавиши остаются на месте при любом масштабе.

## Вязь

Отдельного орнамента не рисовали: вязь кадрируется из логотипа (bright-версия,
`#C1161C`), где она уже есть. `Hem` это нижний подвес с розеткой: сверху он
ставится отражённым (`<Hem open />`) и открывает разворот, снизу закрывает.
Размер регулируется переменной `--weave-width`.

Вязь и логотип в подвале рисуются кистью, поэтому лежат не картинкой, а разметкой:
компонент `Ink` подставляет её инлайном. Файлы `public/bezslavie-weave.svg`
и `public/bezslavie-logo.svg` собраны из исходника `docs/bezslavie-logo-source.svg`
скриптом `docs/split-logo.py` (`python3 docs/split-logo.py` из папки лендинга):

- исходник был одним путём в координатах в шестьдесят раз крупнее рамки, и пунктир
  на нём браузер не рисует вовсе; скрипт переводит путь в координаты рамки;
- просветы в буквах живут только внутри одного пути, поэтому фигура собрана целиком:
  буква и её просвет в одном `path`;
- кисть не обводит фигуру по краю, а закрашивает её змейкой изнутри: строки внутри
  фигуры сшиты в один росчерк, и пропусков в середине букв не остаётся;
- след кисти обрезан по самой фигуре, поэтому переходы змейки не оставляют косых
  полос, а толщина кисти не залезает на соседей;
- в логотипе надпись пишется строками сверху вниз и по буквам слева направо, а венец,
  подвес и боковые ромбы расходятся от середины к краям: части идут разом
  и заканчиваются вместе;
- вязь штрихуется столбцами от середины наружу, правая половина это отражение левой,
  поэтому половины идут кадр в кадр; время змейки считается по её месту в полосе,
  и кисть всегда на фронте волны;
- у логотипа маска в конце снимается: её край второй раз сглаживает контур, и узор
  под ней выходит бледнее обычной заливки.

Отрисовку можно замедлить адресом: `?slow=8` растянет её в восемь раз, до сорока.

Заголовки страниц и слово «Домовой» набраны Ruslan Display и подняты тенью:
плоская заливка в этом шрифте выглядит недорисованной.

## Движение

Всё движение лежит в `src/styles/motion.css` и целиком выключено для тех, кто
попросил покой: `prefers-reduced-motion: reduce` оставляет страницу статичной,
а `Ink` в этом случае даже не вешает маску, поэтому узор виден сразу целиком.

- блоки появляются при прокрутке: `useReveal` вешает класс, анимацию держит CSS;
- первый экран и шапка раздела выходят каскадом по загрузке, вязь рисуется кистью;
- домовой дышит, снимок отзывается на курсор и плывёт по ходу прокрутки там,
  где браузер умеет привязывать анимацию к видимости;
- прокрутка цепляется за секции (`useSnap`), но только за те, что помещаются
  в экран: на длинной главе привязка не давала долистать её за один жест;
- переход между страницами разделов идёт через `@view-transition`.

## Домовой

Картинки лежат в `public/domovoy/<состояние>.webp`, компонент `Domovoy` подставляет
их по ключу состояния. Размер задаётся ростом, а не шириной: позы разной формы, и по
ширине лежащий домовой оказался бы вдвое крупнее стоящего.

| Ключ | Где стоит |
| --- | --- |
| `greeting` | первый экран главной |
| `listening` | раздел «Заявка» |
| `alarmed` | тёмная врезка про инспекцию и раздел «Сроки» |
| `knocking` | раздел «Соседи» |
| `scroll` | раздел «Собрание» |
| `abacus` | раздел «Деньги и счётчики» |
| `walking` | раздел «Дом» |
| `ledger` | раздел «Цифры» |
| `wrench` | раздел «Смена» |
| `clock` | раздел «По часам» |
| `letter` | раздел «Чат» |
| `sleeping-sitting` | финал главной |

Лежачий `sleeping` остался в папке про запас: он широкий и в узкие места не встаёт.

Промпты, по которым они нарисованы, лежат в `docs/domovoy-prompts.md`.

## Сборка

Адрес бота задаётся переменной `VITE_BOT_LINK` и обязателен: без неё сборка и запуск
останавливаются с ошибкой, потому что кнопкам «Открыть в MAX» и ссылке в `noscript`
вести некуда. В разметке страниц она подставляется как `%VITE_BOT_LINK%`.

В `body` каждой страницы лежит `noscript`: что за продукт, ссылка на бота и ссылки на
документы. Без сценариев страница показывает его, а не белый лист.

`npm run build --workspace @bezslavie/landing` собирает страницы разделов, а вместе с ними
карту сайта `sitemap.xml` (её обещает `robots.txt`) и страницу `404.html`. Промах по адресу
отдаёт её сервер продукта: отказом в JSON отвечают только `/api` и `/auth`.

`npm run landing` из корня собирает лендинг и раздаёт `landing/dist` так же, как его отдаёт
продуктовый сервер: разделы по своим адресам, промах по адресу отвечает `404.html`. Порт
задаётся переменной `LANDING_PORT`, по умолчанию 4173.

Рядом с каждым текстовым файлом сборка кладёт сжатые копии `.br` и `.gz`
(`scripts/precompress.mjs`), сервер продукта отдаёт готовую по заголовку `accept-encoding`.
