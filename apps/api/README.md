# apps/api

HTTP-адаптер для мини-приложения на Fastify. Маршруты разбирают запрос, зовут сценарий
из `@domovoy/app` и сериализуют ответ, логики здесь нет.

частоты на этот путь не распространяется. Пока `updates` не передан, маршрута нет и бот
забирает апдейты опросом.

Маршруты домофонии появляются только вместе с `hubSecret`: их зовёт оборудование,
а не человек, и проверяются они общим секретом в заголовке `x-hub-secret`.

## Коды ответов

Ошибки предметной области отображаются по смыслу, а не сваливаются в 400:

| Код | Когда |
|---|---|
| 401 | Токен есть, а профиля за ним нет: приложению нужно войти заново |
| 403 | Роль не вправе выполнить действие или это чужая заявка |
| 404 | Заявка, объект, счётчик, файл или привязываемый житель не найдены |
| 409 | Заявка закрыта или переход из текущего состояния невозможен |
| 400 | Всё остальное, включая проверку схемы запроса |

## Доступ с другого адреса

Если мини-приложение и API живут на разных адресах, нужен список разрешённых источников
(`allowedOrigins`), иначе браузер заблокирует запросы. Задаётся именно список, а не `*`:
запросы ходят с токеном сессии.

Разрешаются три заголовка: `content-type`, `authorization` (токен сессии)
и `x-max-init-data` (строка запуска при входе). Без последнего не пройдёт вход.

## Описание для подключения

`GET /openapi.json` отдаёт описание API в формате OpenAPI 3.1. Оно собрано из тех же схем
Fastify, по которым сервер проверяет запросы и сериализует ответы, поэтому описание
и поведение не расходятся. Внешняя библиотека для этого не используется.

Описание нужно тем, кто подключается к продукту: диспетчерской системе управляющей компании,
выгрузке в ГИС ЖКХ, собственному клиенту. Метрики и раздача статики в описание не входят.

## Схемы ответов

Ответы описаны схемами Fastify: лишние поля наружу не уходят, расхождение с форматом
обнаруживается на сервере.

Сообщения ошибок отдаются как есть только для кодов ниже 500. Остальное превращается
в «Внутренняя ошибка», детали сбоя уходят в лог.

## Несколько домов

Маршруты сотрудника принимают `buildingId` в строке запроса: очередь, сводка, реестр,
объявления, люди, квартиры, исполнители. Права проверяются один раз, при определении того,
кто пришёл; сценарии о переключении не знают.

Жилец на чужой дом получает 403, сотрудник на дом чужой организации тоже. Несуществующий
дом даёт 404, а не пустую очередь.

## Частота запросов

Пределы включены по умолчанию: триста запросов в минуту на сессию и десять на вход.
Триста взяты с запасом: открытие одного экрана стоит нескольких запросов, и человек,
листающий разделы подряд, в предел упираться не должен.
Счёт идёт по токену сессии, а до входа по адресу: за одним адресом может сидеть весь подъезд
через общий Wi-Fi.

Отказ приходит с кодом 429 и заголовком `retry-after`. Проверка живости и приём апдейтов
платформы в предел не упираются: их зовёт не человек.

Отдельно работает предел на подачу заявок: десять в час на жильца. Он реализован
в прикладном слое, поэтому действует и в боте, и в приложении. Сотрудников и заявок
от датчиков не касается.

Счётчики живут в памяти процесса, поэтому при нескольких репликах предел умножается на их
число. Настраивается через `rateLimit`, снимается через `rateLimit: false`.

## Живость и заголовки

`GET /health` обращается к хранилищу и отвечает 503, когда база недоступна. Результат
кешируется на две секунды, чтобы частые проверки не давали нагрузку.

На каждый ответ ставятся три заголовка: `nosniff`, `x-frame-options: DENY`
и `referrer-policy: no-referrer`. Мини-приложению вместо `x-frame-options` отдаётся
`content-security-policy` с `frame-ancestors`.

## Метрики

`GET /metrics` отдаёт состояние службы в формате Prometheus: время работы, память, число
запросов по маршруту и коду ответа, суммарное время ответа. Внешняя библиотека для этого
не используется.

Маршрут в метке берётся из схемы (`/api/requests/:id`), а не из адреса, иначе каждый
идентификатор заявки завёл бы собственный ряд.

Продуктовые показатели (открытые заявки, просрочка, оценки) отдаёт сводка по дому,
а не метрики.

`METRICS_TOKEN` закрывает страницу заголовком `authorization`.

## Склейка в нескольких репликах

Обращения по одному дому обрабатываются последовательно, иначе два соседа, написавших
одновременно, заведут две заявки.

Внутри процесса используется очередь, между репликами распределённая блокировка
(`AppDeps.lock`), та же, что у сессий бота. С `REDIS_URL` она подключается автоматически.
Ключ блокировки берётся по дому, поэтому заявки соседних домов друг другу не мешают.

## Один адрес на всё

Сервер отдаёт и статику: `web.landing` в корень, `web.miniapp` в `/app`. Мини-приложение
работает на том же адресе, что и API, и обращается к нему относительным путём: CORS не нужен,
сертификат один, версии статики и API не расходятся. Маршруты API объявлены раньше статики.

Файлы с отпечатком содержимого в имени (`/assets/`) отдаются с годовым кешем, HTML
с `no-cache`, остальное на час.

Сборка кладёт рядом с каждым текстовым файлом сжатые копии `.br` и `.gz`, сервер отдаёт
готовую по заголовку `accept-encoding`. Ответы API сжимаются на лету от килобайта и выше:
`compress: false` это выключает, `compress: { threshold }` двигает порог.

Мини-приложению разрешено открываться в рамке (`frameAncestors`), остальным путям рамка
запрещена.
