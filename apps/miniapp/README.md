# apps/miniapp

Мини-приложение для клиента MAX: React 19 и Vite, поверх `@maxkit/react` и `@maxkit/bridge`.

Кнопки, поля и переключатели берутся из официального кита платформы `@maxhub/max-ui`:
приложение открывается внутри мессенджера и выглядит как остальные его экраны. Разметка
страницы, карточки и метки описаны в `styles.css`, своих правил для кнопок и полей там нет.

Переменные оформления кит объявляет внутри своей обёртки, поэтому приложение целиком
живёт в `MaxUI`. Тема берётся системной и следит за переключением: её меняют,
не закрывая приложение.

## Навигация

Разделы стоят в нижней панели. В неё помещается пять подписей, шестая обрезается
многоточием, поэтому в панели то, чем пользуются в смену, а редкое уходит в «Ещё».

«Новая заявка» вкладкой не показывается: кнопка стоит на экране заявок.

## Экраны

Названия те же, что человек видит в панели и в заголовке экрана.

| Оплата | всем с квартирой | Квитанция со строками, общедомовыми нуждами и пенями, показания счётчиков, история платежей |

| Наклейки | сотруднику | Плюс лист для печати всего дома и поиск по объектам |

| Действия | управляющему | Кто открыл дверь, снял дежурство, отклонил заявку |
| Роль | всем | Примерить другую сторону продукта. Есть только на установке с `DEMO_ROLES=1` |

Во время объявленных работ заявка не заводится: экран показывает срок и кнопку
«всё равно оставить заявку», текст обращения при этом не теряется.

Панель разделов зависит от роли: диспетчер и управляющий начинают с очереди дома, мастер
и подрядчик, со своих нарядов, жилец, со своих заявок. Разделы, не поместившиеся в панель,
лежат в «Ещё». У смены их много, поэтому они разложены по группам: «Смена», «Дом», «Деньги»,
«Управление» и «Своё», а на установке с `DEMO_ROLES` добавляется «Проверка» с примеркой
роли. Раздел, которому нужен неподключённый поставщик, не показывается вовсе, и по прямой
ссылке на него тоже не попасть: «Дом» без домофонии, «Приём» без приёмных часов, «Наклейки»
без канала доставки файлов.

На разделах висят значки с числом дел, которые ждут именно этого человека: у диспетчера,
новые и просроченные заявки очереди и вопросы жильцов без ответа, у мастера, просроченные
наряды, у жильца, заявки, где ждут его слова или приёмки, и ответы управляющей компании.
Число на кнопке «Ещё», это сумма спрятанных за ней разделов.

Сотруднику в шапке доступен выбор дома. Список ограничен домами его организации.
Переключатель показывается, только когда домов больше одного, смена дома перечитывает
экраны. Жильцу переключатель домов не показывается.

Квартира выбирается там же, но на своих экранах: «Оплата», «Собрания» и «Работа дома».
Переключатель появляется, когда квартир больше одной, и работает у всех, включая сотрудника
и подрядчика. Дом смены при этом не меняется: очередь, план и сводка остаются в своём доме.

Разделы про свою квартиру («Оплата», «Собрания», «Работа дома» и привязка) жильцу и
подрядчику показываются, а смене в рабочем меню нет: сотрудник пришёл работать по дому.
На установке с `DEMO_ROLES` они остаются и у смены, иначе проверяющему негде посмотреть
жильцовую часть. У подрядчика при этом нет ни очереди дома, ни его оборудования: только
свои наряды и своя квартира.

## Голос

Рядом с полем ввода стоит кнопка микрофона: у помощника, в новой заявке и в сообщениях
по заявке и в поддержку. Короткое нажатие оставляет запись идти, долгое работает как
рация; с клавиатуры кнопка переключается Enter. Пока записывается, на кнопке идёт время.

Запись уходит на `POST /api/voice` в base64 и нигде не сохраняется: наружу возвращается
только текст. Расшифровка подставляется в поле, а не отправляется сама: человек должен
увидеть, что распознали, и поправить. Предел записи, два мегабайта.

Где запись браузером недоступна, кнопка подменяется полем выбора файла с `capture`:
пишет системное приложение клиента. Без подключённой расшифровки маршрут отвечает отказом,
и остаётся обычный ввод текста.

## Фото к заявке

Снимок уменьшается на устройстве до 1600 точек по большей стороне и уходит на сервер сразу
при выборе. Неудача с загрузкой снимка заявку не отменяет.

В карточке снимок загружается запросом, а не через `<img src>`: за файлом нужен токен сессии,
а атрибут `src` заголовков не отправляет. Байты живут в blob, пока карточка на экране. Снимок
видят автор и сотрудники того же дома.

Мастер прикладывает снимок результата к переходу «выполнено». Фотография привязана к событию
истории, а не к заявке.

## Показание с фотографии табло

Пока поле показания пустое, рядом с ним стоит «Снять табло». Снимок уходит тем же путём,
что и фотография к заявке, а `POST /api/meters/:id/photo` возвращает распознанное число.
Оно подставляется в поле, подаёт его человек кнопкой «Подать»: ошибиться в цифре на снимке
легко, а показание уходит в начисление. Кнопки нет, если чтение табло в установке
не подключено.

Приложение открывается на привязке, если жилец ещё не связан с квартирой, но не
запирает на ней: объявления дома касаются и непривязанного, а заявку по коду
с наклейки можно оставить вообще без квартиры.

## Возможности клиента MAX

- **Камера читает наклейку.** Из ссылки берётся код объекта, чужой QR отклоняется
  с сообщением.
- **Тактильная отдача** на отправке заявки, приёмке работы и смене отбора.
- **Подтверждение закрытия** появляется, пока в форме есть недописанный текст.
- **Пересылка объявления и наклейки** средствами мессенджера: готовая наклейка уходит
  в переписку с ботом, а оттуда пересылается в любой чат по идентификатору сообщения.
- **Кнопка «назад»** платформы и шифрованное хранилище клиента для сессии.

Перед использованием каждая возможность проверяется у моста: неподдерживаемая кнопка
не показывается.

## Движение

Экран появляется движением, список выходит сверху вниз, строка и крупная кнопка проседают
под пальцем, столбики графиков растут снизу, полоса срока наполняется от нуля, подсказка
первого входа выезжает листом. Правила движения лежат в конце `styles.css` одним блоком
и выключаются при `prefers-reduced-motion: reduce`.

## Вход

Параметры запуска обмениваются на сессионный токен один раз при старте, токен лежит
в шифрованном хранилище клиента. Срок жизни сессии задаётся отдельно от окна доверия
к `auth_date`.

Протухшая сессия заменяется автоматически, без сообщения пользователю.

## Сборка и размещение

```bash
VITE_API_URL=https://api.example npm run build --workspace @domovoy/miniapp
```

`VITE_API_URL` подставляется на сборке. По умолчанию он пустой: приложение ходит в API
относительным путём, потому что его и API отдаёт один сервер. Заполнять переменную нужно,
только если статику раздаёт другой сервер.

Собранное приложение ссылается на свои файлы относительно, поэтому работает и в корне,
и в подпапке: на боевой машине это `/app/`, стенд разработки открывает его из корня.

Две вещи, без которых приложение не заработает у пользователя:

- **HTTPS.** Клиент MAX открывает мини-приложение в вебвью и по HTTP его не отдаст.
- **`ALLOWED_ORIGINS` на стороне API**, если приложение и API живут на разных
  адресах: иначе браузер заблокирует все запросы, и экран останется пустым без
  единой ошибки в интерфейсе. При раздаче с одного адреса это не нужно.

## Разработка и тесты

```bash
npm run dev --workspace @domovoy/miniapp     # Vite
npm test --workspace @domovoy/miniapp        # экраны в настоящем DOM
```

Приложение открывается по адресу `http://localhost:5173/`, но вне клиента MAX мост
не отвечает. Для разработки рядом лежит стенд:

```
http://localhost:5173/stand.html?startapp=eqp_dom15_lift-1
```

Роль клиента мессенджера играет эмулятор из [`@maxkit/devhost`](../../packages/devhost):
приложение работает в рамке, справа панель с лентой событий Bridge, параметры запуска
приходят в hash так же, как их подставляет клиент. Код объекта задаётся в адресе стенда.
Веток «если разработка» в приложении нет.

С `VITE_BOT_TOKEN` параметры запуска подписываются настоящим HMAC, и серверная проверка
подписи проходит. Без токена приложение открывается, но сессию API не выдаёт.

В сборку стенд не попадает: токен бота в клиентском бандле был бы доступен всем.

Тесты собирают исходники в `dist-test` отдельным конфигом: встроенный запускатель Node
не понимает JSX. Экраны рендерятся в happy-dom с эмулятором моста, без клиента MAX и без сети.
