# @domovoy/stickers

Наклейки с кодами объектов дома. Код ведёт в переписку с ботом, в которой объект уже известен:
жильцу не нужно объяснять, где именно сломалось.

Что и куда клеить, решают правила в `@domovoy/domain` (`planStickers`): подъезды и стояки
берутся из квартир дома, оборудование из его карточки, коды квартир печатаются отдельно, для
квитанций. Здесь остаётся рисунок.

## Что внутри

| Функция | Что делает |
|---|---|
| `renderSticker(plan, look)` | Картинка наклейки: код, подпись объекта и своя надпись |
| `renderStickerPng(plan, look)` | Та же наклейка растром: её видно прямо в ленте чата |
| `sheetFor(address, plans, look)` | Лист для печати по списку объектов |
| `renderSheet(address, stickers)` | Лист для печати из готовых рисунков |
| `writeStickers(directory, options)` | Наклейки файлами и лист для печати рядом с ними |

Разметка SVG остаётся исходной формой: она масштабируется без потери качества, надпись в
ней, текст, и её же печатают. Для чата нужна картинка, поэтому рядом лежит отрисовка в
PNG.

## Отрисовка в растр

Растром занимается `@resvg/resvg-js`, шрифт берётся не из системы, а из зависимости
`@expo-google-fonts/roboto`: в контейнере шрифтов обычно нет, и кириллица вышла бы пустыми
квадратами.

Модуль подгружается по требованию: если сборки под платформу нет, `canRasterize()` вернёт
`false`, и продукт продолжит работать, наклейка уйдёт разметкой. Точка сборки проверяет это
один раз при старте и говорит об этом в журнале.

## Стили

Стиль задаёт цвет бумаги, цвет кода, цвет уголков-искателей и форму модулей: квадрат, точка
или скруглённый квадрат. Список стилей лежит в `STICKER_STYLES` домена, поэтому приложение
и бот предлагают одно и то же.

Уголки-искатели рисуются сплошными, а не по модулям: разорванная на точки рамка читается
камерой хуже.

## Своя надпись

`look.note` печатается под подписью объекта и попадает в саму картинку, а не в подпись
к сообщению. Длину ограничивает лист: больше `STICKER_NOTE_MAX_LENGTH` символов не
принимается, слово шире строки обрывается многоточием.
