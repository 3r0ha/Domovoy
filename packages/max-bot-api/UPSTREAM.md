# Происхождение и отличия

Это форк официальной библиотеки **[max-messenger/max-bot-api-client-ts](https://github.com/max-messenger/max-bot-api-client-ts)**.

- Основа: тег `0.3.0`, коммит `03ffdf44173e4e632e512cdb84ded5aabefb59d9`
- Лицензия исходной библиотеки, MIT, файл `LICENSE` сохранён без изменений
- Авторы исходного кода, команда MAX; наш вклад ограничен изменениями из списка ниже

Форк понадобился потому, что часть дефектов невозможно исправить снаружи: они лежат
в местах, у которых нет точек расширения. Всё, что можно было закрыть без форка,
закрыто отдельными пакетами `@maxkit/*`, здесь только то, что иначе не чинится.

## Что перенесено

`src/`, `tests/`, `LICENSE`, `tsconfig.json`.

Не переносились: `examples/` (не компилируются и в самом апстриме, 14 ошибок типов,
проверено сравнением с чистым `main`), `docs/`, `CHANGELOG.md`, конфигурация релизов.

## Изменения

### 1. Своя реализация `fetch` в `ClientOptions`

`src/core/network/api/client.ts`

`createClient` всегда вызывал глобальный `fetch`, а `ClientOptions` содержал только `baseUrl`.
Ни прокси, ни инструментирование, ни тестовый двойник подключить было нельзя.
Соответствует открытому issue [#287](https://github.com/max-messenger/max-bot-api-client-ts/issues/287).

Поведение по умолчанию не изменилось: глобальный `fetch` вызывается через обёртку,
поэтому его подмена в тестах продолжает работать.

### 2. Параметры запроса со значениями `0`, `false` и пустой строкой

`src/core/network/api/client.ts`

При сборке query проверка `if (!value) return` отбрасывала не только незаданные значения,
но и осмысленные: нельзя было явно передать `disable_link_preview=false`, а `marker=0`
не доходил до платформы. Теперь пропускаются только `undefined` и `null`.

### 3. Политика для несогласованного состояния сценария

`src/scenario/engine.ts`, `src/scenario/types.ts`

Прогресс сценария живёт в сессии и переживает выкладку. Если сценарий переименовали, удалили
или изменили набор его шагов, сохранённое состояние перестаёт соответствовать коду: движок
бросает исключение, причём перехват стоит раньше остальных обработчиков, до пользователя
не доходит даже команда отмены, и диалог замирает навсегда.

Добавлена опция `ScenarioEngineOptions.onInconsistentState`:

- `throw`, прежнее поведение, значение по умолчанию;
- `reset`, убрать несогласованное состояние и передать событие дальше по цепочке,
  чтобы пользователь мог начать заново обычной командой.

### 4. Разметка сообщений: подчёркивание, упоминания и скобки в ссылках

`src/helpers/format.ts`

- Добавлен `underline`, в MAX подчёркивание оформляется как `++текст++`, помощника для него не было.
- Добавлены `mention` и `mentionHtml`: упоминание пользователя в MAX оформляется ссылкой
  на `max://user/<id>`, собирать её приходилось вручную.
- `link` теперь пропускает адрес через новый `escapeUrl`. Круглые скобки и пробелы внутри адреса
  закрывают конструкцию `[текст](адрес)` раньше времени, и ссылка на документ вида
  `.../docs_(v2)/page` разваливалась. Прогнать адрес через `escape` было нельзя, он расставляет
  обратные слэши внутри самого адреса, поэтому проблемные символы заменяются процентными кодами.

Проверено, что `<s>` и `<u>` в HTML-разметке MAX допустимы наравне с `<del>` и `<ins>`,
поэтому существующие помощники оставлены как есть.

Не добавлена подсветка фона (`^^текст^^`, `<mark>`): она встречается в описаниях клиента,
но подтверждения в документации Bot API найти не удалось. По той же причине символ `^`
не добавлен в набор экранируемых: лишнее экранирование показало бы пользователю обратные слэши.

### 5. Имя файла в заголовке при загрузке

`src/helpers/upload/upload.ts`, новый `src/helpers/upload/content-disposition.ts`

Имя файла подставлялось в заголовок сырым: `attachment; filename="${fileName}"`.
Значение заголовка передаётся как latin-1, поэтому кириллическое имя вроде
`акт-приёмки.pdf` доезжало до платформы искажённым, кавычка внутри имени закрывала
значение раньше времени, а перевод строки ломал сам заголовок.

Теперь заголовок собирается по RFC 6266: обычный `filename` содержит безопасное
ASCII-имя, а рядом добавляется `filename*=UTF-8''…` с процентным кодированием.
Получатель, который расширенную форму не понимает, использует запасное имя.

Заголовок `X-File-Name` намеренно оставлен без изменений: он не описан стандартом,
и как платформа его разбирает, неизвестно. Открытый issue
[#253](https://github.com/max-messenger/max-bot-api-client-ts/issues/253) о двойном
процентном кодировании имени как раз про эту неопределённость, поэтому добавлять
собственное кодирование там было бы гаданием.

### 6. Всплывающее уведомление в ответе на нажатие кнопки

`src/core/network/api/modules/messages/types.ts`

Тело `POST /answers` в типах содержало только `message`, хотя `CallbackAnswer` принимает
и `notification`, одноразовое всплывающее уведомление тому, кто нажал кнопку. Без поля
короткий ответ на нажатие приходилось слать отдельным сообщением в переписку.
Добавлено `notification?: string`; остальные поля не тронуты.

## Что намеренно не менялось

Цикл опроса и приём вебхука остались как есть, хотя в них тоже есть дефекты: маркер не
переживает перезапуск цикла, продвигается до обработки апдейтов, а ошибка обработчика роняет
весь цикл. Чинить их здесь незачем, эти части полностью заменены `@maxkit/runtime`
(`UpdateSupervisor` и `WebhookReceiver`), и дублировать исправления в неиспользуемом коде
значило бы поддерживать две реализации вместо одной. Разбор дефектов:
[`docs/sdk-gap-analysis.md`](../../docs/sdk-gap-analysis.md).

## Тесты

`npm test --workspace @maxkit/max-bot-api`, 42 теста: 31 из апстрима без изменений
и 11 наших на перечисленные выше изменения.

## Обновление с апстрима

Изменения затрагивают три файла, поэтому перенос новой версии сводится к сравнению:

```bash
git clone https://github.com/max-messenger/max-bot-api-client-ts.git /tmp/upstream
diff -ru /tmp/upstream/src packages/max-bot-api/src
```

Ожидаемые отличия: `core/network/api/client.ts`, `scenario/engine.ts`, `scenario/types.ts`,
плюс добавленные файлы в `tests/`.
