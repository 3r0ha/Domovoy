# @maxkit/bridge

Клиент MAX Bridge: типизированные запросы к клиенту мессенджера, чтение параметров запуска,
проверка подписи и эмулятор клиента для тестов.

Официальный `@maxhub/max-web-app` подключается скриптом и работает с `window.WebApp`.
Здесь то же самое, но обычным пакетом: с типами на каждый метод, отменой запросов
и предсказуемым поведением вне клиента MAX.

## Запрос к клиенту

```ts
import { getBridge } from '@maxkit/bridge';

const bridge = getBridge();
const size = await bridge.getViewportSize({ signal: controller.signal });
```

Каждый запрос уходит со своим `requestId`, ответ сопоставляется с ним, а не с последним
отправленным событием. У методов свои таймауты: у сканера кода и NFC они заведомо больше,
чем у чтения размера окна, человек в это время ищет наклейку, а не смотрит в экран.

Отмена не откладывается «на потом»: `signal` снимает ожидание, освобождает очередь
и не даёт ответу прийти в размонтированный компонент.

## Вне клиента MAX

Bridge отвечает только внутри клиента мессенджера. В обычном браузере приложение
не падает: транспорт определяется сам, а обращения к недоступному мосту приводят
к `MaxBridgeError` с понятным кодом, `isOutsideMax`, `isUnsupported`, `isTimeout`,
`isAborted`, `isPermissionDenied`. Клиент MAX бросает «голые» объекты вида
`{ error: { code } }`, поэтому все ошибки нормализуются в один класс: `instanceof`
работает, стек-трейс есть.

Что именно поддерживает конкретный клиент, отвечает `supportsFeature`: версия приложения
приходит в параметрах запуска, а таблица возможностей вынесена данными.

## Параметры запуска

```ts
import { readLaunchParams, signInitData } from '@maxkit/bridge';

const { initData, initDataUnsafe, platform, version } = readLaunchParams();
```

`initData`, сырая строка для сервера, `initDataUnsafe`, разобранные данные для показа.
Решения о доступе принимает сервер: разбор здесь не проверяет подпись и называется unsafe
не для красоты.

`signInitData` собирает подписанную строку запуска, им пользуются стенд разработки
и тесты, чтобы проходить боевую серверную проверку без клиента MAX.

## Эмулятор клиента

```ts
import { createMockBridge } from '@maxkit/bridge/mock';

const { bridge, client } = createMockBridge({ startParam: 'eqp_b1_lift-1', latencyMs: 150 });
```

Отвечает по тому же протоколу, что и клиент MAX: хранилища, биометрия, NFC, сканер кода,
лимит в десять ключей шифрованного хранилища. Ответы подменяются по одному, поэтому
обработка ошибок проверяется так же легко, как удачный путь. На нём же работает
[`@maxkit/devhost`](../devhost), стенд, в котором мини-приложение открывается без
клиента мессенджера.

## Тесты

```bash
npm test --workspace @maxkit/bridge
```

80 тестов: разбор параметров запуска и битых строк, подпись и её проверка, сопоставление
ответов с запросами, таймауты и отмена, уничтожение моста с незавершёнными запросами,
поведение вне клиента MAX и таблица возможностей по версиям.
